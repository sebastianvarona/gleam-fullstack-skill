## PostgreSQL Setup

### Docker Compose (Development)

The included `docker-compose.yml` provides PostgreSQL for local development:

```bash
make db          # Start PostgreSQL container
make db-down     # Stop PostgreSQL container
```

Default configuration:
- Host: `localhost`
- Port: `5432`
- User: `postgres`
- Password: `postgres`
- Database: `myapp`

If you prefer local PostgreSQL:

```bash
# macOS with Homebrew
brew install postgresql
brew services start postgresql

createdb myapp

# Ubuntu/Debian
sudo apt-get install postgresql
sudo service postgresql start

sudo -u postgres createdb myapp
```

## Migrations with Cigogne

Cigogne manages database schema changes using plain SQL files.

### Creating Migrations

```bash
make migrate-new NAME=create_users_table
```

This creates: `server/migrations/20250421000001_create_users_table.sql`

### Migration File Structure

```sql
-- Up migration (apply)
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Down migration (rollback)
-- DROP TABLE users;
```

### Applying Migrations

```bash
make migrate              # Apply all pending migrations
cd server && gleam run -m cigogne migrate up     # Same thing
cd server && gleam run -m cigogne migrate down   # Rollback last migration
```

### Migration Best Practices

1. **One change per migration**: Don't combine unrelated changes
2. **Make them reversible**: Always include down migrations
3. **Don't modify existing migrations**: Create new ones instead
4. **Test migrations**: Run them on a copy of production data
5. **Use transactions**: Wrap changes in transactions when possible

### Example Migrations

#### Creating a Table

```sql
-- 20250421000001_create_users.sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  role user_role NOT NULL DEFAULT 'viewer',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_email ON users(email);
```

#### Adding a Column

```sql
-- 20250421000002_add_user_profile.sql
ALTER TABLE users
ADD COLUMN name VARCHAR(255),
ADD COLUMN avatar_url VARCHAR(500);
```

#### Creating an Enum

```sql
-- 20250421000003_create_order_status.sql
CREATE TYPE order_status AS ENUM (
  'pending',
  'processing',
  'shipped',
  'delivered',
  'cancelled'
);

ALTER TABLE orders
ADD COLUMN status order_status NOT NULL DEFAULT 'pending';
```

#### Many-to-Many Relationship

```sql
-- 20250421000004_create_user_roles.sql
CREATE TABLE roles (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,
  description TEXT
);

CREATE TABLE user_roles (
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  role_id INTEGER REFERENCES roles(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);

CREATE INDEX idx_user_roles_user ON user_roles(user_id);
CREATE INDEX idx_user_roles_role ON user_roles(role_id);
```

## Type-Safe SQL with Squirrel

Squirrel generates type-safe Gleam functions from `.sql` files.

### CRITICAL: Connection Requirement

**Squirrel MUST connect to a running database to generate code.** It inspects the database schema (columns, types, enums) to ensure the generated Gleam code is perfectly synced with your database.

Before running `make generate-sql`:
1. Ensure PostgreSQL is running (`make db` or check local service).
2. Ensure `DATABASE_URL` is set or default connection parameters in `server/gleam.toml` are correct.
3. Ensure all migrations are applied (`make migrate`).

### Contract-First Development Pattern

To maintain type safety across the stack, follow this workflow:

1. **Define Shared Types**: Create types and JSON decoders in `shared/src/shared/<domain>.gleam`.
2. **Database Migration**: Create and apply the SQL schema.
3. **Write SQL Queries**: Create `.sql` files in `server/src/<domain>/queries/`.
4. **Generate Code**: Run `make generate-sql`.
5. **Implement Service**: Use the generated functions.
6. **Frontend**: Import the shared types and decoders in your Lustre components.

### Workflow

1. Write SQL query in a `.sql` file
2. Run `make generate-sql` (or `gleam run -m squirrel`)
3. Squirrel generates a Gleam module with typed functions

### Query Examples

#### Simple Select

```sql
-- queries/get_user.sql
-- Get a user by email
select id, email, role
from users
where email = $1;
```

Generated function:
```gleam
pub fn get_user(db: pog.Connection, email: String) 
  -> Result(pog.Returned(GetUserRow), pog.QueryError)
```

#### Insert with Return

```sql
-- queries/create_user.sql
-- Create a new user and return the created record
insert into users (email, password_hash, role)
values ($1, $2, $3)
returning id, email, role;
```

#### Join Query

```sql
-- queries/get_user_with_roles.sql
-- Get user with their roles
select 
  u.id,
  u.email,
  u.role,
  array_agg(r.name) as roles
from users u
left join user_roles ur on u.id = ur.user_id
left join roles r on ur.role_id = r.id
where u.id = $1
group by u.id, u.email, u.role;
```

#### Complex Query with Aggregation

```sql
-- queries/get_order_summary.sql
-- Get order summary with total and item count
select 
  o.id,
  o.status,
  o.created_at,
  count(oi.id) as item_count,
  sum(oi.price * oi.quantity) as total
from orders o
left join order_items oi on o.id = oi.order_id
where o.user_id = $1
group by o.id, o.status, o.created_at
order by o.created_at desc;
```


### Best Practices

1. **Document queries**: Add comments explaining the purpose
2. **Use specific columns**: Avoid `SELECT *`
3. **Add LIMIT for lists**: Prevent unbounded queries
4. **Use indexes**: Add indexes for frequently queried columns
5. **One query per file**: Keep queries focused and reusable

## Connection Pooling

Pog provides connection pooling via OTP:

```gleam
let pool_name = process.new_name()

let config =
  pog.default_config(pool_name)
  |> pog.host("localhost")
  |> pog.database("myapp")
  |> pog.pool_size(10)
  |> pog.max_queue_size(50)
  |> pog.idle_timeout(60_000)

let assert Ok(pool) = pog.start_pool(config)
```

### Pool Configuration

- **pool_size**: Number of connections (default: 10)
- **max_queue_size**: Max waiting requests (default: 50)
- **idle_timeout**: Close idle connections after ms (default: 60s)

## Transactions

Execute multiple queries in a transaction:

```gleam
pub fn transfer_funds(db, from, to, amount) {
  pog.transaction(db, fn(conn) {
    use _ <- result.try(sql.deduct_balance(conn, from, amount))
    use _ <- result.try(sql.add_balance(conn, to, amount))
    use transfer <- result.try(sql.record_transfer(conn, from, to, amount))
    Ok(transfer)
  })
}
```

## Common Patterns

### Soft Deletes

```sql
-- Migration
ALTER TABLE users ADD COLUMN deleted_at TIMESTAMP;

-- Query
-- queries/list_active_users.sql
select id, email
from users
where deleted_at is null
order by created_at desc;

-- queries/soft_delete_user.sql
update users
set deleted_at = now()
where id = $1;
```

### Pagination

```sql
-- queries/list_users.sql
select id, email, created_at
from users
where deleted_at is null
order by created_at desc
limit $1 offset $2;
```

### Full-Text Search

```sql
-- Migration
ALTER TABLE posts ADD COLUMN search_vector tsvector;
CREATE INDEX idx_posts_search ON posts USING gin(search_vector);

-- Query
-- queries/search_posts.sql
select id, title, content
from posts
where search_vector @@ plainto_tsquery('english', $1)
order by ts_rank(search_vector, plainto_tsquery('english', $1)) desc
limit 20;
```
